# State management

State management starts by assigning one owner to each value. This lab uses local state for a draft, a reducer for related task transitions, and a calculation for derived progress.

## Choose state by ownership

Different values need different owners:

| Value | Owner | Reason |
| --- | --- | --- |
| Task name draft | `useState` | One component edits a transient string |
| Task collection | `useReducer` | Add, toggle, and remove share transition rules |
| Completed count | Derived during render | The task array already contains the source data |
| Notes from the API | TanStack Query | Remote data has freshness and synchronization rules |

The last distinction prevents a common architecture mistake: copying server data into component state and creating two sources of truth.

## Reducers make transitions explicit

The reducer accepts a discriminated action and returns a new array for every transition.

```tsx
// apps/web/src/labs/core/state-management/components/
// state-management-demo.tsx
function taskReducer(tasks: Task[], action: Action): Task[] {
  switch (action.type) {
    case "add":
      return [
        ...tasks,
        {
          complete: false,
          id: crypto.randomUUID(),
          name: action.name,
        },
      ];
    case "remove":
      return tasks.filter((task) => task.id !== action.id);
    case "toggle":
      return tasks.map((task) =>
        task.id === action.id
          ? { ...task, complete: !task.complete }
          : task,
      );
  }
}
```

The reducer stays pure: it does not render, fetch, focus controls, or write storage. That boundary makes every transition testable with an input array and an action.

## Derive values instead of synchronizing them

The completed count is calculated from `tasks` during render:

```tsx
const [tasks, dispatch] = useReducer(taskReducer, []);
const completed = tasks.filter((task) => task.complete).length;
```

Storing `completed` separately would require every reducer branch to update two values correctly. Derivation removes that synchronization path.

Use a reducer when transitions form one domain and benefit from explicit action names. Keep independent, transient inputs in local state. Move state into the URL when it should survive navigation, and use TanStack Query when the server owns the canonical value.
