# CRUD notes

Create, read, update, and delete (CRUD) operations become production behavior only when contracts, authorization, persistence, cache updates, and failure semantics agree. This lab implements an authenticated notes feature from React to PostgreSQL.

## One feature crosses several boundaries

Each layer has one responsibility and depends inward through explicit types.

- `@zomlab/contracts` defines request and response shapes
- Hono routes validate transport data and translate domain outcomes into HTTP responses
- `NoteService` coordinates use cases without importing HTTP concepts
- `NoteRepository` owns Drizzle queries and user-scoped persistence
- TanStack Query hooks own cache identity and mutation reconciliation

## Ownership is part of every operation

The authenticated user ID is not accepted from the request body. The route reads it from the server-validated session and passes it through the service. Repository updates and deletes include both the note ID and author ID in the same database predicate.

```ts
// packages/database/src/repositories/core/crud.ts
async delete(id: string, authorId: string): Promise<boolean> {
  const rows = await db
    .delete(notes)
    .where(
      and(eq(notes.id, id), eq(notes.authorId, authorId)),
    )
    .returning({ id: notes.id });

  return rows.length > 0;
}
```

This shape prevents a time-of-check to time-of-use gap. The database performs the ownership check and mutation as one operation.

## Missing data is not an infrastructure failure

Owned reads, updates, and deletes return `null` when no matching note exists. The route translates that result to `NoteNotFoundError` and status 404. Database failures remain exceptions and reach the shared error handler, which returns a masked 500 response.

That distinction protects both API meaning and operations:

| Outcome | Public response | Operational meaning |
| --- | --- | --- |
| Invalid body | 422 validation envelope | Caller can correct the request |
| Missing or non-owned note | 404 not-found envelope | Resource is unavailable to this principal |
| Repository exception | Masked 500 envelope | Infrastructure requires investigation |
| Successful create | 201 with the note | A new resource was persisted |

## Mutations reconcile the cache by scope

An update writes the returned note into its detail cache and invalidates every notes list. A delete removes the detail entry and invalidates lists. This is narrower than clearing the entire query cache.

```ts
// apps/web/src/labs/core/crud/hooks/use-update-note.ts
onSuccess: (note) => {
  queryClient.setQueryData(
    queryKeys.notes.detail(id),
    note,
  );
  return queryClient.invalidateQueries({
    queryKey: queryKeys.notes.lists,
  });
},
```

The UI requires confirmation before destructive mutations and restores keyboard focus when the dialog closes.
