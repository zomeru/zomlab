# Architecture

Notes follows the preferred ZomLab architecture: a strict one-way flow from the UI
down to the database. Each layer only talks to the layer below it.

<Mermaid
  chart={`
flowchart TD
  UI[Notes UI - apps/web] --> H[Hooks - TanStack Query]
  H --> C[Hono client hc]
  C --> R[Hono routes /api/notes]
  R --> S[NoteService]
  S --> REPO[NoteRepository]
  REPO --> DB[(PostgreSQL)]
`}
/>

## Layer responsibilities

| Layer | Responsibility |
| --- | --- |
| UI components | Render state, capture input, no business logic |
| Hooks | Wrap TanStack Query, map API errors to messages |
| Hono routes | Validate input with Zod, call the service, shape responses |
| NoteService | Enforce ownership, throw `NoteNotFoundError` |
| NoteRepository | The only layer that touches Drizzle |
| Database | Storage |

## Why the repository exists

Drizzle is never imported outside the repository layer. This keeps the service
testable with a fake repository and makes swapping the storage backend a one-file
change.
