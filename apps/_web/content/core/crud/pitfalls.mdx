# Common Pitfalls

## Leaking Prisma into services

Never `import { db } from "@zomlab/database"` inside a service. Services depend on
the `NoteRepository` interface, which keeps them unit-testable and storage-agnostic.

## Missing ownership checks

Every read, update, and delete must verify `note.authorId === user.id`. Skipping the
check on update is the classic authorization bug: an attacker can overwrite any note
they know the id of.

## Trusting `user` without narrowing

The `requireAuth` guard throws `UnauthorizedError` when there is no session, which
narrows `user` to a defined value in route handlers. If you change the guard to
return `{ user: undefined }` instead, every handler must re-check — easy to miss.

## Forgetting cookie forwarding

In embedded mode, Next.js forwards the request to Elysia on the same origin, so the
session cookie arrives naturally. If you later run the standalone API server, the
browser must send credentials — otherwise `getSession` always returns `null` and
every request 401s.

## 422 vs 400 for validation

Elysia validates bodies with its own schema engine and rejects invalid payloads with
`422 Unprocessable Entity`, not `400`. Tests asserting `400` will fail — assert `422`
or map the error explicitly.
